# 🧠 روش یادگیری و مدیریت AI

**تاریخ:** 18 August 2026  
**هدف:** ذخیره طرز فکر یادگیری برای استفاده بهینه از cloud AIs با کمترین توکن

---

## ۱. طرز فکر یادگیری من (Buffy)

### قانون ۱: "ده بار چالش"
هر مرحله از هر دستور، قبل از اجرا ۱۰ بار خودم را زیر سؤال ببرم:
1. آیا این بهترین راه است؟
2. آیا راه ساده‌تری هست؟
3. آیا این واقعاً لازم است؟
4. آیا این با هدف پروژه همخوانی دارد؟
5. آیا dependency غیرضروری اضافه می‌کند؟
6. آیا این قبلاً حل شده؟
7. آیا این scale پذیر است؟
8. آیا این قابل rollback است؟
9. آیا این با محدودیت‌های سخت‌افزار سازگار است؟
10. آیا AI دیگری این را بهتر انجام می‌دهد؟

### قانون ۲: "خودت را مدیریت کن"
- کارهایی که **من بهتر انجام می‌دهم**: architecture, debugging, code writing, data analysis
- کارهایی که **AI دیگر بهتر انجام می‌دهد**: research (deep), vision/OCR, real-time data
- کارهایی که **انسان بهتر انجام می‌دهد**: authentication, physical actions, decisions

### قانون ۳: "اطلاعات = سرمایه"
- هر اطلاعاتی که یاد می‌گیرم فوراً ذخیره کن
- هر تصمیمی ثبت کن
- هر خطا و درسی ثبت کن
- هر منبعی که پیدا می‌کنم ثبت کن
- **هدف:** هیچ اطلاعاتی دوباره جستجو نشود

### قانون ۴: "Map-based navigation"
- همه اطلاعات به هم متصل باشند
- از یک نقطه بتوان به همه جا رسید
- مثل نقشه شهر: هر خیابان به خیابان دیگر وصل است

## ۲. نقش هر AI در پروژه

### Buffy (من) — مدیر اصلی
- **نقش:** Architecture, Implementation, Debugging, Code, Integration
- **کار:** نوشتن کد، تست، fix، یکپارچه‌سازی
- **نباید انجام دهد:** research عمیق (بهتر است به AI دیگر بدهد)

### Cloud AI 1 — Research Agent
- **نقش:** Deep research, academic papers, latest strategies
- **کار:** جستجوی عمیق در منابع, مقایسه, ارزیابی
- **example prompts:** "جدیدترین استراتژی‌های ICT را از ۱۰ منبع معتبر مقایسه کن"
- **Token budget:** کم (فقط خلاصه نتیجه بده)

### Cloud AI 2 — Data Analysis Agent
- **نقش:** تبدیل اطلاعات به اعداد, statistical analysis
- **کار:** محاسبه win rate, profit factor, drawdown
- **example prompts:** "این نتایج بک‌تست را تحلیل کن و confidence interval بده"
- **Token budget:** متوسط

### Cloud AI 3 — Content Extraction Agent
- **نقش:** استخراج محتوا از ویدیو, متن, تصویر
- **کار:** OCR, transcription, concept extraction
- **example prompts:** "این ویدیو را ببین و استراتژی‌هایش را استخراج کن"
- **Token budget:** بالا ( ولی فقط وقتی لازم باشد)

### Cloud AI 4 — Validation Agent
- **نقش:** اعتبارسنجی ادعاها و نتایج
- **کار:** cross-reference, fact-checking
- **example prompts:** "آیا این ادعا در ۳ منبع مستقل تأیید شده؟"
- **Token budget:** کم

## ۳. نحوه مدیریت همزمان AIها

### الگوی کار
```
User Request
     │
     ▼
Buffy (مدیریت)
     │
     ├──→ Research Agent: تحقیق عمیق → نتیجه خلاصه
     ├──→ Data Agent: تحلیل اعداد → نتیجه عددی
     ├──→ Content Agent: استخراج محتوا → متن ساختاریافته
     └──→ Validation Agent: اعتبارسنجی → true/false + منبع
     │
     ▼
Buffy: یکپارچه‌سازی + اجرا + ذخیره
```

### نحوه پس‌دادن توکن
به هر AI بگویم:
> "فقط خلاصه نتیجه را بده. کد یا توضیح اضافه نده. حداکثر ۲۰۰ کلمه."

## ۴. نکات کاهش مصرف توکن

### برای Research Agent:
```
Prompt: "از ۵ منبع معتبر درباره [موضوع] تحقیق کن. 
فقط: 
۱. نام منبع + لینک
۲. خلاصه ۳ جمله‌ای
۳. امتیاز اعتماد (1-5)
حداکثر ۳۰۰ کلمه."
```

### برای Data Agent:
```
Prompt: "این داده‌ها را تحلیل کن:
[داده‌ها]
فقط: win_rate, profit_factor, max_drawdown, sharpe_ratio
فرمت: JSON
حداکثر ۱۰۰ کلمه."
```

### برای Content Agent:
```
Prompt: "از این متن/ویدیو استراتژی را استخراج کن.
فقط:
۱. نام استراتژی
۲. Entry rule
۳. Exit rule
۴. Stop loss
۵. Take profit
۶. Timeframe
۷. نمادها
فرمت: JSON
حداکثر ۲۰۰ کلمه."
```

### برای Validation Agent:
```
Prompt: "این ادعا را بررسی کن:
[ادعا]
آیا در این منابع تأیید شده؟
فقط: true/false + منبع
حداکثر ۱۰۰ کلمه."
```

## ۵. ذخیره‌سازی برای انتقال

### هر فایل باید شامل باشد:
1. **Metadata:** تاریخ, منبع, نوع, اهمیت
2. **Content:** محتوای واقعی
3. **Connections:** ارتباط با فایل‌های دیگر
4. **Confidence:** سطح اطمینان
5. **Status:** verified/unverified/outdated

### فرمت ذخیره‌سازی:
```markdown
## [ID]: [عنوان]
- **تاریخ:** YYYY-MM-DD
- **منبع:** [نام منبع]
- **نوع:** [strategy/data/decision/lesson]
- **اهمیت:** [high/medium/low]
- **اطمینان:** [verified/unverified/outdated]
- **ارتباط:** [فایل‌های مرتبط]
- **محتوا:**
  [محتوای واقعی]
```

## ۶. چگونه از Cloud AI استفاده کنیم

### سناریو ۱: تحقیق استراتژی جدید
```
Prompt: "از پوشه trading-bot/docs/STRATEGIES.md شروع کن.
جدیدترین استراتژی‌های ICT/SMC را از ۱۰ منبع معتبر (YouTube, Reddit, Academic) تحقیق کن.
فقط: نام, win rate, profit factor, منبع, لینک
حداکثر ۵۰۰ کلمه."
```

### سناریو ۲: بک‌تست استراتژی
```
Prompt: "از پوشه trading-bot/docs/STRATEGIES.md شروع کن.
استراتژی [نام] را با داده‌های [symbol] از [تاریخ] تا [تاریخ] بک‌تست بگیر.
فقط: win_rate, profit_factor, max_drawdown, total_trades, sharpe
فرمت: JSON"
```

### سناریو ۳: اعتبارسنجی منبع
```
Prompt: "از پوشه trading-bot/docs/KNOWLEDGE_BASE.md شروع کن.
ادعای [ادعا] را در ۵ منبع مستقل بررسی کن.
ف┮: true/false + منبع + سطح اطمینان
حداکثر ۲۰۰ کلمه."
```

### سناریو ۴: استخراج محتوا
```
Prompt: "از این لینک [URL] استراتژی معاملاتی را استخراج کن.
فرمت خروجی:
{
  "name": "...",
  "entry": "...",
  "exit": "...",
  "stop": "...",
  "target": "...",
  "timeframe": "...",
  "symbols": ["..."],
  "confidence": 0.0-1.0
}
حداکثر ۳۰۰ کلمه."
```

## ۷. سلسله‌مراتب تصمیم‌گیری

```
Level 1: آیا این کار واقعاً لازم است؟
    ├── No → متوقف شو
    └── Yes → Level 2

Level 2: آیا من می‌توانم این را خودم انجام دهم؟
    ├── Yes → Level 3
    └── No → به AI دیگر بده

Level 3: آیا راه ساده‌تری وجود دارد؟
    ├── Yes → Level 3 (تکرار)
    └── No → Level 4

Level 4: آیا این با architecture پروژه همخوانی دارد؟
    ├── No → گزارش تعارض + پیشنهاد جایگزین
    └── Yes → Level 5

Level 5: آیا این dependency غیرضروری اضافه می‌کند؟
    ├── Yes → حذف dependency
    └── No → Level 6

Level 6: اجرا + تست + ذخیره نتیجه
```

## ۹. چرخه یادگیری مداوم

```
هر روز:
├── بررسی استراتژی‌های جدید (10 min)
├── بررسی نتایج تریدها (5 min)
├── به‌روزرسانی knowledge base (5 min)
└── بررسی منابع جدید (10 min)

هر هفته:
├── بازنگری استراتژی‌ها (30 min)
├── بهینه‌سازی risk parameters (15 min)
├── بررسی performance (15 min)
└── مستندسازی lessons (15 min)

هر ماه:
├── بازنگری کلی architecture (1 hour)
├── بررسی tools جدید (30 min)
├── بهینه‌سازی token usage (15 min)
└── مستندسازی تصمیمات (30 min)
```
